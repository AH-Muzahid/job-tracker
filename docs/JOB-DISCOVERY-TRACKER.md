### Phase 3: UX & Search Infrastructure (P2 — Target: 3–6 Months)

- [x] **`REC-13` [Architecture] Two-Tier Hybrid RecSys Engine (pgvector Retrieval + Deep Cross-Encoder Re-Ranking)**
  - **Issue**: Reliance on heuristic regex iterations and in-memory scoring leads to blind keyword counting, domain mismatch false positives, and scalability bottlenecks.
  - **Action**: Implemented enterprise two-tier hybrid recommendation system: (1) Tier 1: Sub-30ms dense vector retrieval directly inside PostgreSQL via `pgvector` HNSW cosine distance index (`canonical_job_embedding_hnsw_idx`, `vector_cosine_ops`) over 1536-dimensional OpenAI embeddings (`text-embedding-3-small`), including dead link elimination (`isValidJobPostingUrl`) and negative aversion token subtraction (-0.25 on repeatedly dismissed roles); (2) Tier 2: Sub-800ms deep cross-encoder re-ranking using Google `gemini-2.0-flash` with structured Zod schema output (`generateObject`), enforcing 100-point rubric (Skills 40, Role 25, Location 20, Seniority 15), objective domain specialization lockout (role score <= 5/25 for frontend vs devops mismatch), and contextual candidate project match proofs (`Proof: <project> validates ...`).
  - **Target Files**: `prisma/schema.prisma`, `scripts/migrate-vector-hnsw.ts`, `src/lib/discovery/embedding.ts`, `src/lib/discovery/vector-retrieval.ts`, `src/lib/discovery/ai-reranker.ts`, `src/lib/discovery/matching.ts`, `src/lib/discovery/scrapers.ts`, `prisma/seed-discovery.ts`, `src/app/api/jobs/discover/route.ts`, `src/components/discovery/types.ts`, `src/__tests__/rec-sys-two-tier.test.ts`
