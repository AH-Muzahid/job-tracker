# Design System Inspired by Stripe

## 1. Visual Theme & Atmosphere

Stripe's design system embodies a premium, tech-forward aesthetic designed for financial infrastructure at scale. The visual personality is clean, trustworthy, and progressive—balancing professional minimalism with vibrant, gradient-driven hero moments. The system uses expansive whitespace, generous typography, and a restrained color palette punctuated by bold accent colors (deep purple and emerald green) that signal confidence and forward momentum. Decorative gradients flow across hero sections in soft, diagonal sweeps, creating visual interest without overwhelming the content. The overall mood is sophisticated yet approachable—a system built for enterprise users who expect both polish and clarity.

**Key Characteristics**
- Minimalist canvas with soft neutral backgrounds (`{colors.canvas}` — `#F6F9FC`)
- Bold primary accent (`{colors.primary}` — `#533AFD`) used sparingly for critical CTAs
- Generous negative space and hierarchical typography
- Soft, flowing decorative gradients in hero sections
- Smooth, micro-interactions with subtle elevation and transform effects
- Multi-semantic accent colors deployed in decorative contexts (gradients, bands)
- Enterprise-grade accessibility and touch-target sizing

### Principles
- **Negative Letter Tracking:** Display sizes employ negative letter-spacing (-0.96px to -1.4px) to tighten letterforms and increase visual impact. This is a defining trait of the brand voice.
- **Weight Progression:** Headings use 500 weight (medium) to balance clarity with approachability. Body text is uniformly 300 (light) for visual openness.
- **Line Height Ranges:** Tighter line heights on display (1.03–1.21) focus impact; generous line heights on body (1.4–1.6) improve readability.
- **Semantic Sizing:** Navigation and labels are precisely 15px / 300-weight to create consistent, scannable interface text.
- **Hierarchy Through Scale:** Display roles jump to 48–56px; headings sit at 24–38px; body at 14–18px. This creates clear visual hierarchy without relying solely on weight.

## 5. Layout Principles

### Spacing System

Base unit: `{spacing.xs}` = `8px`

Spacing scale with context:

- `{spacing.xxs}` = `4px` — Micro-spacing between text and icons, tight inline margins
- `{spacing.xs}` = `8px` — Button internal padding, small component gaps
- `{spacing.sm}` = `12px` — Form field spacing, list item separation
- `{spacing.md}` = `16px` — Default padding for cards, standard section margin
- `{spacing.lg}` = `20px` — Larger component padding, medium section gaps
- `{spacing.xl}` = `24px` — Card internal spacing, content container padding
- `{spacing.xxl}` = `32px` — Large section separation, major layout divisions
- `{spacing.xxxl}` = `36px` — Extended section spacing
- `{spacing.section}` = `40px` — Main section top/bottom padding
- `{spacing.band}` = `48px` — Hero band and major layout section padding

### Grid & Container

**Max Width Strategy:**
- Mobile (375px): Full width minus gutters; content width ~363px
- Tablet (768px): Max content ~736px with 16px gutters on each side
- Desktop (1024px+): Max content width ~1248px at 1440px viewport

**Column Layout:**
- All viewport sizes use an 8-column grid
- Grid aligns to 16px baseline
- Gutters: 16px on sides; internal column gaps consistent

**Section Patterns:**
- Full-bleed hero sections span viewport width with `padding: {spacing.band}` (`48px`) vertical
- Content sections center within max-width container with horizontal padding `{spacing.md}` (`16px`)
- Nested sections use 12-column subdivision within parent 8-column structure

### Whitespace Philosophy

Stripe's design prioritizes expansive negative space to create visual breathing room and guide focus. Sections are separated by generous vertical padding (`{spacing.band}` or `{spacing.section}`), and internal component spacing uses consistent multiples of the base 8px unit. Empty space is treated as a design element, not a void—it creates hierarchy, reduces cognitive load, and signals premium positioning.

### Border Radius Scale

- `{rounded.none}` = `0px` — Sharp edges on images, full-width sections
- `{rounded.xs}` = `2px` — Badge borders, minimal rounding
- `{rounded.sm}` = `4px` — Buttons, form inputs, icon buttons
- `{rounded.md}` = `5px` — Alternative mid-range radius (rare; used in specific contexts)
- `{rounded.lg}` = `6px` — Cards, elevated surfaces, overlays
- `{rounded.xl}` = `8px` — Large overlays, modals, expanded containers
- `{rounded.full}` = `9999px` — Pill-shaped buttons, circular badges (rare in Stripe's system)

### Border Widths

- **Thin** (`1px`) — Used on card borders, input fields, outline buttons, and subtle dividers
  - Applied to: Card hairline, form input borders, secondary button outlines, section separators

## 6. Depth & Elevation

Stripe uses a progressive shadow system to create visual hierarchy without overwhelming the interface. Elevation increases for modals, dropdowns, cards, and custom overlay regions.

| Level | Treatment | Use |
|---|---|---|
| Flat | No shadow | Default buttons, cards on canvas, navigation |
| Micro | `rgba(50, 50, 93, 0.25) 0px 6px 12px -2px, rgba(0, 0, 0, 0.3) 0px 3px 7px -3px` | Custom components; subtle lift |
| Small | `rgba(50, 50, 93, 0.25) 0px 50px 100px -20px, rgba(0, 0, 0, 0.3) 0px 30px 60px -30px` | Modals, dialog boxes, significant elevation |
| Medium | `rgba(0, 0, 0, 0.1) 0px 18px 36px -18px, rgba(50, 50, 93, 0.25) 0px 30px 45px -30px` | Dropdown menus, floating panels, secondary elevation |
| Large | `rgba(50, 50, 93, 0.25) 0px 13px 27px -5px, rgba(0, 0, 0, 0.3) 0px 8px 16px -8px` | Card surfaces, elevated containers, primary elevation |

**Shadow Philosophy:**
Shadows use dual-layer compositing—a warm shadow layer (black @ 30% opacity) combined with a color shadow (dark gray @ 25% opacity, offset inward). This creates depth that feels natural and cohesive. Larger shadows (-20px to -30px blurs) are reserved for the most elevated elements (modals), while subtle shadows (6–13px blurs) handle card and dropdown elevation. The system avoids harsh drop-shadows, preferring soft, directional light that suggests a light source above and to the upper left.

### Opacity Levels

- `0.15` (15%) — Disabled states, very faint overlays
- `0.20` (20%) — Subtle hover effects, faint text
- `0.50` (50%) — Significant transparency; semi-opaque overlays, reduced emphasis
- `0.70` (70%) — Moderate opacity; emphasized secondary elements
- `0.85` (85%) — Near-full opacity; minimal transparency
- `1.00` (100%) — Full opacity; primary elements

### Z-index / Layering

| Layer | Z-index | Use |
|---|---|---|
| Base / Content | 1–3 | Page content, cards, default elements |
| Dropdown | 10–99 | Dropdown menus, select lists, popovers |
| Sticky | 100, 999 | Fixed/sticky headers, navigation bars |
| Modal / Overlay | 999+ | Modal dialogs, full-screen overlays |
| Toast / Alert | 999999 | Toast notifications, top-level alerts |

## 7. Do's and Don'ts

### Do
- Use `{colors.primary}` (`#533AFD`) exclusively for primary CTAs and critical interactive moments
- Maintain generous negative space between sections; never crowd content beyond `{spacing.band}` (`48px`)
- Apply button padding consistently: large buttons `15.5px 24px 16.5px 24px`, small buttons `11.5px 20px 12.5px 20px`
- Use `{colors.canvas}` (`#F6F9FC`) as the default page background; layer card surfaces at `#F8FAFD` or `#E5EDF5` for depth
- Set heading text to `{colors.ink}` (`#000000`) and body to `{colors.body}` (`#3F4B66`) for consistent contrast
- Apply border-radius `{rounded.sm}` (`4px`) to all interactive elements (buttons, inputs, icon controls)
- Use negative letter-spacing (-0.96px to -1.4px) on display text (48–56px sizes) to tighten large headlines
- Pair navigation font `{typography.nav}` (15px, 300 weight) with hover opacity reduction (0.6) for consistency
- Deploy decorative gradients in hero sections using provided CSS; reserve solid colors for UI
- Test all interactive states (hover, focus, active) with box-shadow and opacity shifts defined in component specs

### Don't
- Override `{colors.primary}` for secondary CTAs; use outline or light-filled variants instead
- Add shadows to buttons; keep them flat (`box-shadow: none`)
- Use sharp corners (0px radius) on interactive elements; maintain `{rounded.sm}` minimum
- Crowd sections with padding under `{spacing.band}` (`48px`); respect visual breathing room
- Apply the secondary accent (`{colors.accent}` — `#0A2540`) to interactive UI; reserve it for decorative bands and overlays
- Mix font weights carelessly; headings are 500 weight, body is 300, and buttons are 400
- Deploy drop-shadows on cards; use only the progressive elevation shadows defined in Section 6
- Set body text smaller than `{typography.body-sm}` (15px); text below this size reduces readability at standard viewing distance
- Forget focus states on links and buttons; always include box-shadow outlines with 2–4px border-radius
- Use `{colors.ink}` on backgrounds; reserve it for text and icon marks only

## 9. Agent Prompt Guide

### Quick Color Reference

Use these semantic mappings for rapid implementation:

- **Primary CTA Button Fill:** Primary (`#533AFD`)
- **Secondary CTA Button Fill:** White or light fill with Primary border
- **Page Background:** Canvas (`#F6F9FC`)
- **Card / Surface Background:** Light tinted (`#F8FAFD` or `#E5EDF5`)
- **Heading Text:** Ink (`#000000`)
- **Body Text:** Body (`#3F4B66`)
- **Secondary Text / Captions:** Muted (`#4F5B76`)
- **Placeholder / Disabled Text:** Faint (`#64748D`)
- **Borders / Dividers:** Hairline (`#E5EDF5`)
- **Inline Links:** Link (`#0000EE`)
- **Decorative Accents / Gradients:** Accent 2–5 (see Section 2)

### Iteration Guide

1. **Set Base Typography:** All body text is `{typography.body-md}` (16px, 300 weight, 1.4 line height). Headings use 500 weight; buttons use 400 weight. Display text (48–56px) applies negative letter-spacing (-0.96 to -1.4px).

2. **Button Styling:** All buttons have `border-radius: {rounded.sm}` (4px). Primary buttons are `#533AFD` filled; secondary buttons are outline (`1px solid #B9B9F9`). Padding is `15.5px 24px` for large (48px height), `11.5px 20px` for small (40px height). Hover state reduces opacity to 0.6.

3. **Card Elevation:** Cards use `border-radius: {rounded.lg}` (6px). Background is `#F8FAFD` (default) or `#E5EDF5` (elevated). Shadows follow the progressive scale: micro for subtle, large for prominent elevation. No shadow on flat cards.

4. **Spacing:** Use multiples of 8px. Default section padding is `{spacing.band}` (48px) vertical, `{spacing.md}` (16px) horizontal. Never drop below `{spacing.md}` for breathing room.

5. **Navigation:** Nav links are `{typography.nav}` (15px, 300 weight). Hover state applies opacity 0.6. Primary button in header is `#533AFD` filled; secondary is outline or white.

6. **Focus & Interaction:** All interactive elements have `:focus` state with `box-shadow: var(--focusBoxShadow)` and `border-radius: 2px` or `4px`. Hover states adjust opacity or background color per component spec. Active states match hover for consistency.

7. **Responsive Grid:** Use 8-column grid across all breakpoints. At 375px, content is single-column (363px wide). At 768px+, enable multi-column layouts. Heading size scales: 34px (mobile) → 48px (tablet) → 56px (desktop).

8. **Color Hierarchy:** Primary accent (`#533AFD`) is reserved for primary CTAs. Secondary accents (`#0A2540`, `#15BE53`, etc.) are decorative only. Text hierarchy uses Ink > Body > Muted > Faint. Never invert this order.

## 10. Known Gaps

- **Interaction States:** The extraction observed hover, focus, and active states in stylesheets, but specific CSS values for state transitions (e.g., exact color on button hover for all variants) are not fully measured. Implementations should test empirically.
- **Semantic Color Ramp (Error/Success/Warning):** The site does not declare explicit error, success, or warning colors in its markup. Status colors are not part of the measured system; if needed, they should be custom-defined.
- **Dark Mode / High-Contrast Variants:** Only one theme was extracted (light). A dark mode or high-contrast variant, if it exists, was not analyzed; this document represents the measured light theme only.
- **Animation & Transition Timing:** Transform effects (translateY, scale, etc.) are noted in interaction state data, but duration and easing curves are not measured. Implementations should define transitions (e.g., `transition: all 200ms ease-out`).
- **Micro-interactions Beyond Hover/Focus/Active:** Gesture-based interactions, scroll effects, and parallax behaviors are outside the extraction scope.
- **Decorative Accent Color Usage:** Seven colors (`{colors.accent-1}` through `{colors.accent-5}`, plus Accent and Primary) are present but lack assigned semantic roles. They are treated as decorative pending further site analysis.
- **Form Validation States:** Specific styling for invalid, success, or warning input states was not extracted. Input focus behavior is measured, but error-state styling is absent.
- **Cross-Origin Asset Loading:** Some CSS files are served cross-origin and may not have been fully readable during extraction, so component styling details (e.g., certain pseudo-class behaviors) may be incomplete.
- **Authenticated Surfaces:** Pages behind authentication were not visited; styling for user account, dashboard, or logged-in contexts is outside this document's scope.
- **Print Styles:** Print media styling was not measured.
- **Line Height on Button Components:** One button entry (`{typography.button-md}`) lacks measured line height; implementations should infer from similar button roles or test empirically.
